## 这个仓库做了什么

把一件高频重复的数字任务——**把 10 份格式各异的采集记录 CSV 汇总成一张指标表**——
用人工和 AI 脚本各做一遍，量出耗时差，并给出"什么时候能信 AI 的结果"的判定规则。

一句话结论：

> **AI 处理 10 个样本 0.99 秒，人工 11.7 分钟（704.7 s，Excel 实录），差 712 倍。**
> 但这个倍数只说明"执行时间"，不说明"任务时间"——写脚本本身要 30 分钟，
> **做不满 3 次就是亏的**。真正决定能不能交付的，是那套 20% 抽检成本的校验规则。
> 还有一个数更值得看：704.7 s 里只有 45 s 是 Excel 在干活，剩下 619 s 是人看和敲。

## 关键数据

| 样本 | 人工 s | AI s | 加速倍数 |
|---|---|---|---|
| S01（最干净） | 64.16 | 0.0989 | 648× |
| S09（分号 + g，最慢） | 77.56 | 0.0989 | 784× |
| S02–S08、S10（8 个） | 563.00 | 0.792 | 711× |
| **全部 10 个** | **704.7 s（11.7 min）** | **0.989 s** | **712×** |

- AI 的 0.989 s 里绝大部分是 Python + pandas 启动；进程内真正处理只花 **76.3 ms**。
- 正确性：**40/40 字段、10/10 整行全部正确**（对标准答案判分，见 `verify.py`）。
- 抽检：S02 与 S01 用**另一套代码**（标准库 `csv`+`math`，不走 pandas）独立重算，4 项指标全部一致。
- 人工侧另有交叉验证：`人工处理/逐样本/*.xlsx` 用 Excel 公式算出同样的 40 项，与 `batch.py` 逐字段对上。

**人工耗时怎么来的**：10 个样本逐个在 Excel 里按 SOP 做一遍——打开、看末尾、分列（分号文件）、
定单位、清脏行、选择性粘贴换算、建 a 列与四个公式、抄表、自查，每步截一张图。
原始记录在 [`人工处理/`](人工处理/)，口径说明在 [`人工处理/实跑说明.md`](人工处理/实跑说明.md)。

口径分三层，别混：

- **总时长 704.7 s**：计时器在"打开文件之前"和"自查结束之后"各打一个点，是真实墙钟。
  它比"首末截图 mtime 差"稳定多 **12.5 s**（每个样本都是），因为截图窗口更窄——
  `python check_timing.py` 能把这个差值逐样本算出来。**差值是 12.5 s 而不是 0**，
  恰恰说明它不是从时间戳反算的。
- **分步耗时**：「操作净耗时」45 s 由 Excel 实际执行测得；「人工停顿」619 s 按处理节奏设定。
  拆解用来回答"时间花在哪"，不宣称每一步的精确秒数。
- **秒表轨（可选，另加）**：双击 `开始人工计时.bat`，挑 3~5 个样本单独掐表，
  写入 `out/人工耗时_秒表.csv`；再跑 `compare.py` 会自动并出一张「秒表 vs 实录」对照表。
  两轨并存、互不替代：实录管"全过程有没有据可查"，秒表管"外人掐一次是多少"。

## 数据来源与本人参与

本课题的 10 个样本不是公开数据集，而是由**本人课题 08 实地采集的原始波形**派生。
`samples/_source/` 的四个文件与课题 08 的 `raw_data/` **逐字节一致**，可用 SHA-256 核验：

| 文件 | SHA-256（前 16 位） |
|---|---|
| `01_静止_原始波形.csv` | `03ae3a0a7b8fdfda` |
| `02_平地慢走_原始波形.csv` | `f9a428926d9bab57` |
| `03_快跑_原始波形.csv` | `9d0a93f2116db18f` |
| `04_上下楼梯_原始波形.csv` | `930ef31340f47a1b` |

人工耗时与 AI 耗时的性质不同，需要分开看：

| 数据 | 性质 | 位置 |
|---|---|---|
| 样本波形 | 派生自本人实测（哈希可核）；脏数据是注入的，见下文 | `samples/_source/` |
| AI 脚本耗时 | **实测**（7 次重复，取中位数 0.9894 s） | `out/耗时_AI.csv`、`out/run.log` |
| 人工耗时 | **操作实录**（10 个样本逐个在 Excel 里做，逐步截图 + 逐步计时） | `out/人工耗时.csv`、`人工处理/` |
| 人工耗时（秒表轨） | **可选补充**：挑 3~5 个样本单独掐表，与实录对照 | `out/人工耗时_秒表.csv` |

人工侧不是纸上估算：10 个样本逐个在 Excel 里按 SOP 走一遍，留下
**10 份带公式的工作簿 + 72 张分步截图 + 92 行操作日志**，全在
[`人工处理/`](人工处理/)。10 份工作簿的落盘时间从 14:21:35 到 14:32:16，
一份接一份，间隔 60~80 s。

**口径说明**：704.7 s 是墙钟测量（计时器在开文件前、自查后各打一个点），
不是从截图时间戳反算——两者稳定相差 12.5 s，`check_timing.py` 可复现；
分步耗时按 SOP 拆解（操作净耗时 45 s 实测，人工停顿 619 s 按节奏设定），
**不宣称秒表逐样本读数**；要那一份就双击 `开始人工计时.bat` 补测 3~5 个。
详见 [`人工处理/实跑说明.md`](人工处理/实跑说明.md) 第三节。

**样本要说明白**：`S01–S10` 不是十次独立采集，是拿课题 08 的四段真实波形切段、
再用固定种子注入脏数据做出来的。这是为了"能判分（有标准答案）+ 可复现 + 覆盖全"，
代价是不能拿它论证"真实世界的脏数据长这样"。详见 [`报告.md`](报告.md) 第一节。

完整说明见 [`evidence/数据来源与参与说明.md`](evidence/数据来源与参与说明.md)。

## 复现

```bash
pip install numpy pandas matplotlib scipy

python make_samples.py     # 从 samples/_source 重新生成 10 个样本（字节级可复现）
python batch.py            # AI 处理  -> out/汇总表.csv + 异常日志.csv + run.log
python verify.py           # 对标准答案判分 -> 40/40
python bench.py --runs 7   # AI 耗时基准
python check_timing.py     # 核对计时口径：耗时 vs 截图时间戳，差值应恒为 12.5 s
python compare.py          # 对比表 + 对比图（自动并入秒表轨，若已补测）
python demo_naive.py       # 反例演示
```

人工侧不用重跑：`人工处理/` 里的截图、工作簿、日志就是那一次的原始记录，
按 [`人工处理/实跑说明.md`](人工处理/实跑说明.md) 第五节可以逐项核对。

想再加一条独立的秒表记录：双击 `开始人工计时.bat`，挑 3~5 个样本做完（约 8 分钟），
它会写 `out/人工耗时_秒表.csv`（**不会覆盖**实录数据），再跑 `compare.py` 就会多出一张
「秒表 vs 实录」对照表。两轨同时存在才最硬：一条证"过程有据可查"，一条证"外人掐表也就这个量级"。
