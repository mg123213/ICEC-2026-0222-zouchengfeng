# 课题 10 · AI Prompt 记录

> 目标：让 AI 一次写出能处理 10 份格式各异的样本、并把「改了什么」登记下来的批处理脚本。
> 下面是实际使用的提示词，可直接复用；末尾附三条迭代提示词，对应脚本开发中真实踩到的坑。

---

## 主提示词（一次性投喂）

```
你是一名数据工程助手。我有一个高频重复的数字任务：把 10 份采集记录 CSV 汇总成一张表。

【输入】samples/ 下 10 个 CSV，每份约 600 行，列是 时间 + 三轴加速度。
但它们格式不统一，已知存在这些差异：
  - 分隔符可能是逗号或分号
  - 表头可能是英文（Time (s), ax (m/s^2)）或中文（时间(s), X轴加速度(g)）
  - 时间单位可能是 s 或 ms
  - 加速度单位可能是 m/s^2 或 g
  - 混有空行、整行重复、以及末尾以 # 开头的备注行
  - 文件带 UTF-8 BOM

【输出】一张汇总表，每个文件一行，字段：
  文件名 / 样本数 / 有效时长_s / 峰值_a / RMS_a / 原时间单位 / 原加速度单位
其中 a = √(ax²+ay²+az²)，峰值 = max(a)，RMS = √(mean(a²))。
统一换算到 m/s^2 和 s 之后再算（g × 9.80665）。

【另外要求】
1. 再输出一张异常日志表：每个文件被删掉几个空行、几个重复行、几行备注、做了哪种单位换算。
2. 每处理一个文件记录耗时（毫秒）。
3. 写一个 run.log，记录脚本自身的 sha256、输入文件的合并 sha256、处理文件数、总耗时。
   目的是事后能证明"这份结果是哪个版本、基于哪批输入跑出来的"。
4. 不要硬编码文件名，目录用参数传入。

【边界】哪个文件的单位识别不出来，就明确报错并跳过，不要猜。
```

**产出**：`batch.py`（约 150 行）。一次性可用，10/10 正确。

## 迭代提示词（开发中真实用到的三条）

### ① 分隔符判断失效

```
`pd.read_csv` 默认只认逗号，S06 和 S09 是分号分隔的，读进来只有一列。
改成先读第一行、数一下逗号和分号哪个多再决定 sep，不要用 sep=None 去猜
（引擎猜错时不会报错，会静默把整行塞进一列，后面全错）。
```

**产出**：`sniff_delimiter()`。这里的关键不是"能读出来"，而是**读错了要能被发现**——
所以异常日志里记了 `原始行数`，如果分隔符判断错，`样本数` 会和 `原始行数` 对不上。

### ② 空行统计被 pandas 吞掉

```
`skip_blank_lines=True` 会直接把空行丢掉，导致我拿不到"删了几行空行"这个数。
不要为了统计去关掉它（关了以后 dropna 逻辑会变复杂），
改成单独扫一遍原始文本数空行数。
```

**产出**：`n_blank` 单独统计。这里的教训是：**统计口径和执行逻辑要分开**，
让执行路径保持简单，统计走旁路。

### ③ 单位换算写错位置

```
第一次给的脚本先把三轴换算成 m/s^2，但时间还是 ms，导致"有效时长"小了一千倍。
单位换算必须在算指标之前一次性做完，并且把换算动作记进异常日志。
```

**产出**：换算统一放在 `sort_values` 之前，日志里写 `×9.80665` 或 `—`。

## 提示词写法上的三条经验

| 做法 | 为什么有效 |
|---|---|
| 把"已知会脏成什么样"列清楚 | AI 不会主动防御它没被告知的异常；列出 6 类已知问题后，脚本一次就覆盖全了 |
| 要求输出异常日志，而不只是结果 | 结果对不对没法当场判断，**"改了几行"能当场判断**——这是最快的自检信号 |
| 明确要求留痕（脚本 hash + 输入 hash） | 批处理最大的风险是"跑了但不知道跑的是哪版"；留痕让返工可追溯 |

> **反面例子（可复现）**：如果只写一句"把 CSV 汇总成一张表"，
> 拿到的多半是最直观那种写法——`pd.read_csv(path)` 直接读、算完不换算。
> 跑 `demo_naive.py` 就能看到后果：分号文件整行挤进 1 列（该行全空），
> g 单位文件的峰值只剩真值的 1/9.8，样本数还多算 2 行。
> **三个错一个都不报。** 所以提示词里"已知会脏成什么样"这一段不是客套，是防这个的。
