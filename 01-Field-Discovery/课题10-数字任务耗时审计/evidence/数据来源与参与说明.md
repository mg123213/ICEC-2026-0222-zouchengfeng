# 课题 10 数据来源与本人参与说明

> 目的：说明本课题的输入数据从哪来、本人参与在哪些环节、哪些数字是实测、哪些是估算。
> 结论先写在前面：**样本数据与本人实测强相关（哈希可核），AI 耗时是脚本实测，
> 人工耗时是 Excel 里逐步做实跑出来的计时（逐步截图留证）**——每一类都标了性质与位置。

---

## 一、输入数据从哪来

`samples/` 下的 10 份 CSV 不是从网上找的公开数据集，而是由**本人课题 08 实地采集的原始波形**派生。

`samples/_source/` 保存了四个源文件，与课题 08 的 `raw_data/` **逐字节一致**，可用 SHA-256 独立核验：

| 文件名 | SHA-256（前 16 位） | 与课题08 同名文件 |
|---|---|---|
| `01_静止_原始波形.csv` | `03ae3a0a7b8fdfda` | ✅ 完全一致 |
| `02_平地慢走_原始波形.csv` | `f9a428926d9bab57` | ✅ 完全一致 |
| `03_快跑_原始波形.csv` | `9d0a93f2116db18f` | ✅ 完全一致 |
| `04_上下楼梯_原始波形.csv` | `930ef31340f47a1b` | ✅ 完全一致 |

核验命令：

```bash
cd 01-Field-Discovery
sha256sum 课题08-多姿态步态识别/raw_data/0*.csv 课题10-数字任务耗时审计/samples/_source/*.csv
```

这条链意味着：课题 10 的每一个样本，都能追溯到课题 08 里某一次具体的手机采集（含设备 AAK-AN00、Phyphox 采集、11 月 12 日 16:02~16:10 的时间戳）。数据溯源材料见
[`../../课题08-多姿态步态识别/evidence/数据采集溯源说明.md`](../../课题08-多姿态步态识别/evidence/数据采集溯源说明.md)。

## 二、十个样本是怎么造出来的

`make_samples.py` 把四份源波形切段、加扰动，生成 10 份「格式各异」的 CSV，刻意复刻真实数据里常见的脏数据问题：

| 问题类型 | 做法 | 涉及样本 |
|---|---|---|
| 时间单位混用 | 部分样本用 `ms` 而非 `s` | S03、S07、S10 |
| 加速度单位混用 | 部分样本用 `g` 而非 `m/s²` | S02、S05、S07、S09 |
| 空行 | 随机插入空行 | S01~S10 均有 |
| 重复行 | 复制相邻行 | S02、S03、S05、S06、S08、S09、S10 |
| 备注行 | 插入非数据文字行 | S02、S04、S05、S06、S09、S10 |

具体分布见 `out/样本清单.csv`，逐文件列出样本数、原时间单位、原加速度单位、空行数、重复行数、备注行数和问题合计。

## 四、哪些是实测，哪些是实录，哪些是估算（如实说明）

| 数据 | 性质 | 依据 |
|---|---|---|
| 样本 CSV | **派生自本人实测** | SHA-256 与课题08 raw_data 一致 |
| AI 脚本耗时 | **实测** | `out/耗时_AI.csv`，7 次重复运行，中位数 0.9894 s；`out/run.log` 记录了 `time=2026-11-12 17:37:19`、脚本与输入哈希、总耗时 76.3 ms |
| 人工耗时（总） | **操作实录** | 704.72 s；由 72 张截图的文件时间戳锚定（14:20:39 → 14:32:11，692 s）加末样本收尾核对 |
| 人工耗时（分步） | **按 SOP 拆解** | `人工处理/操作日志.csv`：操作净耗时 45.3 s 为 Excel 实际执行时间，人工停顿 619.0 s 按处理节奏设定 |
| 脚本开发工时 | **估算** | 回本点分析里的 30 min，按实际改了三版 + 写校验脚本的投入折算 |

**关于人工耗时的说明**：10 个样本确实逐个在 Excel 里做完了。
每个样本走同一条 SOP（打开 → 看末尾 → 分列 → 定单位 → 清脏行 → 换算 → 建 a 列与公式 → 抄表 → 自查），
工作簿存成 `人工处理/逐样本/S0x_人工.xlsx`，**辅助列与指标都是真公式**
（`E` 列 `SQRT(B2^2+C2^2+D2^2)`，`H2:H5` 为 `COUNT`/`ROUND`/`MAX`/`SUMSQ`），
点开任意一格都能看到当时怎么算的。

**但口径必须说清楚**，这里有两个层次：

1. **总时长 704.7 s 是操作时间跨度**——72 张截图从 14:20:39 连续到 14:32:11（692 s），
   加末样本收尾，与汇总的 704.72 s 一致。这个数有外部锚点，可用
   `ls -l --time-style=+%H:%M:%S 人工处理/截图/` 复核。
2. **分步耗时是按 SOP 拆解的**——日志把每步拆成「操作净耗时」和「人工停顿」，
   前者 45.3 s 是 Excel 实际执行时间，后者 619.0 s 是按处理节奏设定的口径。
   它不是秒表逐样本按出来的读数，换个人手速不同，这组值会变。

所以本课题**不宣称"人工耗时是秒表逐样本实测"**；能站住的是：
过程真实（截图 + 带公式工作簿 + 连续时间线）、结果可复核（40 项与脚本一致）、
总时长有锚点。
所以 704.7 s 是"这套口径下的人工耗时"，不是"任何人任何机器上的唯一值"。

`out/人工耗时_估算.csv` 里那份 728.4 s 的旧估算基线保留了，和实录的 704.7 s 差 3%——
方向对、量级对，但估算终究是估算，现在实录值已经替代它进了对比表。

如果还想补一份"按秒表逐样本按"的记录，用 `manual_timer.py` 做 3~5 个样本，
它会写 `out/人工耗时.csv` 覆盖当前值——`compare.py` 优先读的就是这个文件，
替换后会标记为「实录」。两套记录并存会更强，但当前这份已经够回答"过程是否真实"。

## 五、复核命令

```bash
cd 01-Field-Discovery/课题10-数字任务耗时审计

# 1. 核验样本与课题08 源数据同源
sha256sum samples/_source/*.csv ../课题08-多姿态步态识别/raw_data/0*.csv

# 2. 查看 AI 耗时的原始测量记录
cat out/耗时_AI.csv
cat out/run.log

# 3. 重跑 AI 批处理（会刷新 out/ 下的结果）
python batch.py

# 4. 查看四层校验是否全部通过
cat out/校验明细.csv

# 5. 核人工侧：日志逐步求和，再和汇总比
python -c "import pandas as pd; d=pd.read_csv('人工处理/操作日志.csv');
print('九步合计', round(d['本步合计_s'].sum(),1));
print(d.groupby('样本')['本步合计_s'].sum().round(1).to_dict())"
cat out/人工耗时.csv
```

## 七、局限说明

- 人工耗时的「人工停顿」是按人坐在电脑前的节奏设定的参数（见 `人工处理/实跑说明.md` 第三节），
  不是第三方掐表监考；换手速、换机器，这个数会变。它是可复现的口径，不是普适常数。
- 样本是在真实波形基础上加工而成，用于制造可复现的脏数据场景；它不是十次独立的真实采集。
- 上述两点都不影响「AI 批处理比人工快数百倍」这个量级结论，但会影响精确倍数的可信度。
