# 用户反馈收集说明

目标：**8 位真实用户**，每人给一条可用反馈（评分 + 一句具体意见）。
要求是"真实"，所以流程设计成 3 分钟内能完成，避免对方敷衍或你代填。

---

## 一、准备

把下面的链接发给对方，手机或电脑都能直接打开，不用装任何东西：

```
https://wbapp-afaouz2pxzdkqew3f4th4r.app.workbuddy.host/?sharecode=YBY6WAHAYJ
```

线上版提交反馈后，页面会多出一段可复制的记录 —— 因为云端容器重建时文件可能被清空，
**让对方把那段复制发给你**，你再补录到本机 `feedback/responses.jsonl`（格式见下）。

**方式 B（几个人凑在一台电脑前）**

1. 启动程序：`python app.py`，浏览器会打开 `http://127.0.0.1:8765/`
2. 提前在「通知解析」里粘贴一条真实通知，确认能出结果（别在同学面前当场翻车）
3. 准备好这条通知的原文，方便让对方自己试一次

## 补录线上反馈

线上收到的记录形如：

```json
{"ts": "2026-11-18T14:20", "role": "普通同学", "score": 4, "useful": ["截止时间提取"], "comment": "群消息里「下周三之前」识别不出来", "would_use": true}
```

原样追加一行到 `feedback/responses.jsonl` 即可，字段与网页提交完全一致。

## 二、单人流程（约 3 分钟）

1. **让对方自己操作**，你不要代点。给他一条真实通知（班级群里最近的一条就行），
   让他粘贴 → 点「解析通知」。
2. 让他看结果，问三个问题：
   - 「截止时间对不对？」
   - 「材料清单有没有漏？」
   - 「这个结果你敢直接照着做吗？」
3. 打开「使用反馈」标签页，让他自己打分、勾选、写一句意见。**不要替他写。**
4. 如果他想说但不想打字，你照他原话记下来，事后追加到 `feedback/responses.jsonl`，
   并在 comment 里注明"口述，本人确认"。

## 三、8 人怎么选

建议覆盖不同使用场景，不要全是同班同学：

| 建议人数 | 身份 | 为什么找他 |
| --- | --- | --- |
| 2 | 班长 / 团支书 | 转发通知最多，最清楚漏通知的代价 |
| 2 | 学习委员 | 管选课、补考、重修，通知最杂 |
| 2 | 普通同学 | 真实接收方，能判断结果可不可信 |
| 1 | 实训室管理员 / 实训课代表 | 器材核对模块的直接用户 |
| 1 | 班主任 / 辅导员 | 从发布方视角看通知要素是否被正确理解 |

## 四、问什么才有用

避免"好用吗""还行吧"这类无法改进的回答。优先问这几类：

**能定位问题的**
- 这条通知里，工具没识别出来的东西是什么？
- 结果里的截止时间和你理解的一样吗？如果不一样，你按哪个走？
- 地点抽成了「00前将以下材料交至行政楼」，你会不会被误导？

**能判断价值的**
- 如果没有这个工具，你刚才会怎么处理这条通知？大概花多久？
- 你会把它加进每天的习惯吗？为什么？

**能提需求的**
- 你最希望它多认哪种说法？（"下周三之前""本周内""三个工作日"……）

## 五、记录与核验

- 网页提交的会直接写进 `feedback/responses.jsonl`，一人一条，不要重复提交
- 全部收完后跑：`python tools/export_feedback.py`，生成 `docs/用户反馈汇总.md`
- 汇总表里的每一条都要能对上具体的人（自己心里有数即可，文件里不存姓名）

## 六、不要做的事

- 不要一个人填 8 条。评分分布会高度雷同（比如全是 4 分、评语结构一致），一眼能看出来。
- 不要让同一个人重复提交来凑数。
- 不要把"我朋友说挺好"写进反馈——那是转述，不是用户反馈。
- 反馈里出现的问题**要真的去改**，改完在 CHANGELOG 里注明"由第 N 位用户反馈触发"，
  这条链路本身就是评分点。
