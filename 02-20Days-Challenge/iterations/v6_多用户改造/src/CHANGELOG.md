## v0.6.0 — 2026-11-17

**从"一个公共页面"改成"每人一个账号、只看自己的数据"。**

之前谁打开链接都看到同一份内容，同学用起来会互相看到待办，也没法统计谁在用。
这一版把账号体系补上，并加了管理员后台。

**账号与安全**

- 学号 + 密码注册登录。密码存 PBKDF2-HMAC-SHA256（12 万次迭代）+ 每用户独立随机盐，
  数据库里没有明文；单元测试专门断言了这一点。
- 登录失败不区分"学号不存在"和"密码错误"，返回同一句话——否则等于送了个枚举学号的接口。
- 同一学号连续失败 5 次锁 5 分钟（内存计数，不引入 redis）。
- 会话用 32 字节随机 token，存 HTTP-only Cookie，30 天过期，退出即失效。

**数据隔离**

- `tasks` 和 `feedback` 都带 `user_id`，所有查询按当前会话过滤。
- 改状态、删除这类写操作也带 `user_id` 条件，跨用户操作直接不命中。
- 学生访问 `/admin` 与 `/api/admin/*` 一律 403。

**管理员后台**

- `2024400222` 注册后自动是 admin（白名单在 `core/auth.py`）。
- 后台三块：概览（8 个指标 + 近 7 天日志柱状 + 事件分布）、注册用户、全部待办与反馈。

**存储从 JSON 换成 SQLite**

多用户之后，JSON 文件要么每次全量读写，要么自己写锁，很容易出现两个人同时保存时
互相覆盖。SQLite 是标准库自带的，仍然零第三方依赖，但给了事务和并发控制。
数据库文件 `data/app.db` 已加入 `.gitignore`。

**界面**

按白灰蓝重做：去掉渐变和大阴影，用 1px 边框 + 极浅投影，三个页面（登录 / 工作台 / 后台）
共用一套变量。学生页面不再显示全局统计，只留自己的待办数和最近截止时间。

**测试**

- 15 条账号单元测试（`tests/test_auth.py`）：注册、重名、弱密码、明文检查、登录、会话、
  退出、限流、跨用户读写
- 17 项端到端冒烟（`tools/smoke_test.py`）：未登录拦截、注册登录、数据隔离、越权访问、页面权限

## v0.5.0 — 2026-11-17

**支持发布为在线应用。** 目的不是替代本地运行，而是解决一个现实问题：
8 位反馈用户没法用你电脑上的程序，而且本地服务一关机就没了。

改动：

- **监听地址按环境变量切换**。检测到 `PORT` 就绑 `0.0.0.0`（云端沙箱由平台注入），
  否则仍只绑 `127.0.0.1`（本机隐私优先）。云端端口不能自动让位，本机仍会避开占用。
- **修一个只有上线才会暴露的问题**。平台网关要求每个请求都带 `sharecode`，
  而浏览器发起的 `<link>` / `<script>` 不会自动带主页面的查询参数，结果样式表和脚本
  全部 403，页面变成没有样式的裸 HTML。而且网关转发前会把 `sharecode` 从 query 里剥掉，
  服务端也读不到它 —— 所以第一次发布出去其实是不可用的。
  改法：云端模式把 CSS/JS **内联进 HTML**，整页只有一次请求；后续 fetch 由前端
  从 `location.search` 取 `sharecode` 自行拼上。
- **反馈可带走**。沙箱容器重建会清空文件，线上提交反馈后会额外返回一段可复制的
  JSON 记录，提交者发回来即可补录到本机 `feedback/responses.jsonl`。
- 页脚按环境显示「纯本地运行」或「线上演示版」。

**线上地址**：<https://wbapp-b57fhwpr7sd7umxxjlmtff.app.workbuddy.host/?sharecode=CUQ24FLKNH>

> 线上版和本地版是同一份代码，行为差异只有存储位置与监听地址。
> 作业要求的连续运行日志仍然只由本机产生 —— 云端容器里的日志不会回流到仓库。

## v0.4.0 — 2026-11-17

**界面与细节修正。** 这一版的问题不是评测跑出来的，是**截图人工核对**发现的——
说明只靠离线指标会漏掉呈现层的问题。

- **空态提示遮挡结果**。`.empty` 用了 `display:grid`，会覆盖 `hidden` 属性默认的
  `display:none`，导致解析结果出来后「解析结果会显示在这里」仍然叠在卡片上方。
  加一条 `[hidden] { display: none !important; }` 全局兜底。
- **动作抽取串到材料里**。`《学生困难补助申请表》` 里的「请」被当成祈使句开头，
  抽出 `请表》一式两份，需班主任签字`。给动词加前置断言 `(?<![\u4e00-\u9fa5])`，
  并补上「交至/报送/送至」等动词。
- **带空格的座机号识别不了**。`0755-8888 0000` 中间有空格，旧正则要求连续数字，
  结果联系人和电话只出了一半。
- **日报每天少一条收尾日志**。汇总写在 `daily_run_end` 之前，统计永远看不到它。
  调整顺序：先写收尾，再汇总。
- 标签页切换抽成 `switchTab()`，支持 `?tab=tasks` 直达和 `?demo=1` 自动演示，
  方便录屏与截图。
- 补三张界面截图到 `docs/screenshots/`。

版本号改为从 `/api/health` 读取，前端不再写死。

## v0.3.0 — 2026-11-17

**修复 v0.1 的第 2 号缺陷，并处理「无截止通知」的误报。** 触发依据：v0.2.0 评测仍有 3 条
挂在时间解析上（选课取成开始时间、图书馆延时被当成截止、补考通知被强行识别出截止）。

改动：

- **区间识别**。`11月18日9:00至11月22日24:00` 这类表达，以前取到了开始时间，
  是最危险的一类错误——用户照着 11-18 准备，实际截止是 11-22。现在扫描相邻候选之间的
  连接符（至/到/—/~/～），把前者标记为区间起点、后者标记为终点，终点加 0.15 分、起点减 0.50 分。
- **支持 `24:00`**，按当日 23:59 处理，贴合「今晚 12 点截止」的日常理解。
- **负向语义识别**。三类位置上的时间不算截止：起始语（`自……起`）、活动安排语
  （`定于……举行/进行`）、区间起点。命中负向信号的候选，若附近 15 字内没有
  「截止/不晚于/请于」这类强锚点，直接剔除；全部候选都被剔除时返回 `None`，
  界面提示「未识别到截止时间」。
- **修了一个隐蔽的定位错误**：判断上下文时用的是「绑定时刻之后」的位置，
  导致 `11月20日起` 里的「起」被跳过、08 号用例一直修不掉。改为用日期本身
  的结束位置（新增 `date_end` 字段）。
- **地点加提交语境门槛**。整篇没有交至/报送/集合/领取这类动作时，不再输出「提交地点」——
  「图书馆延长开放时间」里的图书馆不是要交材料的地方。

**评测对比**

| 截止时间完全命中 | 62.5% | 62.5% | **100%** |
| 地点命中 | 50.0% | 87.5% | **100%** |
| 材料全部召回 | 62.5% | 100% | 100% |
| 三项全过 | 12.5% | 62.5% | **100%** |

单元测试 20 条全绿（`python tests/test_core.py`）。

> 需要说明的是：8 条语料是自建的，100% 只证明在这批写法上稳定，不代表泛化能力。
> 后续每次遇到新写法都应该先补进 `data/samples/` 再改代码，否则评测数字会虚高。

## v0.2.0 — 2026-11-17

**修复 v0.1 的第 1、3、4、5 号缺陷。** 触发依据是 v0.1 基线评测：地点命中只有 50%，
材料全部召回只有 62.5%，说明这两块的抽取逻辑从根上就是错的，补正则没有意义。

改动：

- **地点改为扫描式抽取**。旧版用一条正则硬套，从动词处开始匹配得到
  `00前将以下材料交至行政楼`。新版先定位「楼/室/馆/厅/中心」等后缀词，
  再向前回溯最多 6 字、遇到「至/在/到/前/将」立即停止，向后接房间号（`302室`、`B305`）；
  优先取带「交至/报送至/在……集合」提示语的句子，并跳过「办公室」这类泛称。
- **材料改为四步流水线**：去括号补充说明 → 按逗号分句 → 剥掉「请……携带」动词前缀 →
  按顿号/和/及/以及拆分。支持「一式两份」这种中式数量写法，新增「签字笔、回执、作品集」
  等 8 个材料名，加了「截止/时间/确认/填写」等 9 个动作黑名单防止把句子当材料。
- **标题**截到第一个句末标点，去掉 `@全体成员` 前缀，避免整段群消息当标题。
- **联系人**过滤「教务科、学生处、团委」等 15 个部门名，不再当成人名。

**评测对比**

| 指标 | v0.1.0 | v0.2.0 |
| --- | --- | --- |
| 截止时间完全命中 | 62.5% | 62.5% |
| 地点命中 | 50.0% | **87.5%** |
| 材料全部召回 | 62.5% | **100%** |
| 三项全过 | 12.5% | **62.5%** |

剩余 3 条失败集中在时间解析（区间取开始时间、起始语误判、无截止通知强行识别），
留给 v0.3.0。

## v0.1.0 — 2026-11-17

**首个可运行版本。** 通知解析 + 待办清单 + 器材核对 + 脱敏日志四块骨架打通，
服务端用标准库 `http.server`，前端原生 JS，零第三方依赖。

完成内容：

- `core/telemetry.py`：JSONL 逐日日志，meta 字段白名单 + 正则脱敏，时间戳精确到分钟带时区
- `core/timeparse.py`：中文时间解析，支持 `11月21日17:00`、`2026年11月25日（周三）18:00`、
  `本周五下午4点半`、`三个工作日内` 等写法，按「截止」锚点词打分
- `core/notice_parser.py`：标题 / 截止 / 地点 / 材料 / 联系人 / 动作 / 标签提取，附原文依据
- `core/inventory.py`：借出与归还按「编号 + 借用人」对齐，算数量差与超期天数
- `app.py` + `web/`：本地 Web 界面，四个标签页
- `tools/daily_run.py`：每日自动解析 inbox、自检、生成日报、更新 summary.csv
- `tests/eval_parser.py`：8 条固定语料的离线评测

**已知问题**（由评测和单元测试暴露，下一版修复）：

1. `11月18日9:00至11月22日24:00` 取成了开始时间 11-18，应取结束时间；
2. `图书馆自11月20日起……` 把起始语当成了截止时间，属于误报；
3. 地点抽取会带上动词前缀，得到 `00前将以下材料交至行政楼` 这种脏值；
4. 材料清单拆条不完整：`《申请表》一式两份，需班主任签字` 没拆干净，`成绩单` 漏抽；
5. 群消息里的材料项（`带学生证`）因为整句过长被丢弃；
6. 日报统计不含当次 `daily_run_end` 事件（汇总早于收尾日志写入）。

自检脚本在首次运行时捕获到一个真实缺陷：归还登记表的表头写的是「归还人」，
别名表里只有「借用人」，导致整张归还表读不进来、核对结果恒为空。已在 v0.1.0 内修复。
