## ① 运行日志（25 分）

### 在哪

```
process_logs/
├── 2026-11-17.jsonl       # 每天一份，一行一个事件
├── summary.csv            # 每日汇总：事件数/错误率/平均耗时/P95
└── reports/
    └── 2026-11-17.md      # 自动生成的当日日报
docs/运行日志汇总.md        # 全部日期汇总成一份（提交用）
```

### 怎么证明是真实自动化运行

1. **日志由程序自己写**，不是手填。写入代码在 `core/telemetry.py:event()`，
   每次调用 `app.py` 的接口或 `tools/daily_run.py` 都会产生记录。
2. **有定时任务**。`tools/install_task.ps1` 注册 Windows 计划任务，每天 08:10 与 19:30 自动跑，
   开机错过会补跑（`-StartWhenAvailable`）。
3. **日志与代码改动能对上**。`CHANGELOG.md` 里每次修复的问题，都能在同期日志里找到对应的
   错误记录（例如 `self_check_failed`）。
4. **每天有 git commit**。`chore(logs)` 开头的提交就是当天的日志同步，提交时间与服务端记录一致。

### 脱敏怎么做的

| 项目 | 处理 | 代码位置 |
| --- | --- | --- |
| 时间戳 | 精确到分钟 + 时区，无毫秒 | `telemetry.py:_daily_path / event` |
| 用户身份 | 6 位随机会话哈希 | `Telemetry.__init__` → `self.session` |
| 通知原文 | 完全不写，只记字符数 | `_ALLOWED_META_KEYS` 白名单 |
| 姓名/手机号/学号 | 正则替换 | `_SCRUB_RULES` |
| 错误信息 | 只留异常类型与首行，截 200 字 | `event()` 内 `_scrub_text` |

白名单是**机制性**的：不在 `_ALLOWED_META_KEYS` 里的键会被直接丢弃，
不是靠写代码的人记得别写。单元测试 `test_scrub_meta_drops_unknown_keys` 守着这条。

### 还差什么

**天数。** 今天（11-17）是第 1 天。要满 7 天，需要真的运行到 11-23。

两条路，自己选：

- **路径 A（推荐）**：装计划任务，让机器自己跑 7 天，11-24 交作业。
  ```powershell
  powershell -ExecutionPolicy Bypass -File tools\install_task.ps1
  ```
  期间电脑要开着（睡眠也行，`-StartWhenAvailable` 会补跑）。每天不需要你做任何事。
- **路径 B（赶时间）**：如实写「截至提交日已连续运行 N 天」，
  把日志质量（脱敏、指标、错误记录）和其余两项做扎实，靠质量补天数。

**不要做的**：改时间戳造 7 天。文件有创建时间、git 有提交时间戳、服务端也有一份，
三处对不上就是硬伤，而且这个评分点本身就叫「防摆拍」。
