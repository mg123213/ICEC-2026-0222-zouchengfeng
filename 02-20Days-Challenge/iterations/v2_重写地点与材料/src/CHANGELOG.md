# 变更记录

记录每次提交解决的具体问题，以及判断依据（评测数字 / 日志证据 / 用户反馈）。
版本号遵循 `主版本.次版本.修订号`，修订号递增对应一次真实提交。

## v0.2.0 — 2026-11-17

**修复 v0.1 的第 1、3、4、5 号缺陷。** 触发依据是 v0.1 基线评测：地点命中只有 50%，
材料全部召回只有 62.5%，说明这两块的抽取逻辑从根上就是错的，补正则没有意义。

改动：

- **地点改为扫描式抽取**。旧版用一条正则硬套，从动词处开始匹配得到
  `00前将以下材料交至行政楼`。新版先定位「楼/室/馆/厅/中心」等后缀词，
  再向前回溯最多 6 字、遇到「至/在/到/前/将」立即停止，向后接房间号（`302室`、`B305`）；
  优先取带「交至/报送至/在……集合」提示语的句子，并跳过「办公室」这类泛称。
- **材料改为四步流水线**：去括号补充说明 → 按逗号分句 → 剥掉「请……携带」动词前缀 →
  按顿号/和/及/以及拆分。支持「一式两份」这种中式数量写法，新增「签字笔、回执、作品集」
  等 8 个材料名，加了「截止/时间/确认/填写」等 9 个动作黑名单防止把句子当材料。
- **标题**截到第一个句末标点，去掉 `@全体成员` 前缀，避免整段群消息当标题。
- **联系人**过滤「教务科、学生处、团委」等 15 个部门名，不再当成人名。

**评测对比**

| 指标 | v0.1.0 | v0.2.0 |
| --- | --- | --- |
| 截止时间完全命中 | 62.5% | 62.5% |
| 地点命中 | 50.0% | **87.5%** |
| 材料全部召回 | 62.5% | **100%** |
| 三项全过 | 12.5% | **62.5%** |

剩余 3 条失败集中在时间解析（区间取开始时间、起始语误判、无截止通知强行识别），
留给 v0.3.0。

## v0.1.0 — 2026-11-17

**首个可运行版本。** 通知解析 + 待办清单 + 器材核对 + 脱敏日志四块骨架打通，
服务端用标准库 `http.server`，前端原生 JS，零第三方依赖。

完成内容：

- `core/telemetry.py`：JSONL 逐日日志，meta 字段白名单 + 正则脱敏，时间戳精确到分钟带时区
- `core/timeparse.py`：中文时间解析，支持 `11月21日17:00`、`2026年11月25日（周三）18:00`、
  `本周五下午4点半`、`三个工作日内` 等写法，按「截止」锚点词打分
- `core/notice_parser.py`：标题 / 截止 / 地点 / 材料 / 联系人 / 动作 / 标签提取，附原文依据
- `core/inventory.py`：借出与归还按「编号 + 借用人」对齐，算数量差与超期天数
- `app.py` + `web/`：本地 Web 界面，四个标签页
- `tools/daily_run.py`：每日自动解析 inbox、自检、生成日报、更新 summary.csv
- `tests/eval_parser.py`：8 条固定语料的离线评测

**基线评测（2026-11-17 00:45）**

| 指标 | 数值 |
| --- | --- |
| 截止时间完全命中 | 62.5% |
| 地点命中 | 50.0% |

**已知问题**（由评测和单元测试暴露，下一版修复）：

1. `11月18日9:00至11月22日24:00` 取成了开始时间 11-18，应取结束时间；
2. `图书馆自11月20日起……` 把起始语当成了截止时间，属于误报；
3. 地点抽取会带上动词前缀，得到 `00前将以下材料交至行政楼` 这种脏值；
4. 材料清单拆条不完整：`《申请表》一式两份，需班主任签字` 没拆干净，`成绩单` 漏抽；
5. 群消息里的材料项（`带学生证`）因为整句过长被丢弃；
6. 日报统计不含当次 `daily_run_end` 事件（汇总早于收尾日志写入）。

自检脚本在首次运行时捕获到一个真实缺陷：归还登记表的表头写的是「归还人」，
别名表里只有「借用人」，导致整张归还表读不进来、核对结果恒为空。已在 v0.1.0 内修复。
