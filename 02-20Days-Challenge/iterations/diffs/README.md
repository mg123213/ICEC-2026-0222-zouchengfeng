# 迭代 Diff 记录

评分点②要的是「基于日志的至少 3 次 Git 迭代 Diff」。这里放了 **5 份**。

每份是**相邻两个可运行版本之间的完整差异**（`diff -ruN`），与上级目录里的同名快照一一对应：

- 想知道**改了什么** → 看这里的 `.diff`
- 想知道**改成什么样** → 进上级目录里对应的 `vN_xxx/src/`，直接 `python app.py` 就能跑

| # | 区间 | diff 行数 | 触发依据（可复查） |
| --- | --- | --- | --- |
| 01 | v1 → v2 | 351 | 评测：地点 50%、材料 62.5%，判定为抽取逻辑缺陷 |
| 02 | v2 → v3 | 275 | 评测：3 条挂在时间解析（区间、起始语、无截止误报） |
| 03 | v3 → v4 | 242 | 截图人工核对：空态遮挡、动作串词、座机号、日报时序 |
| 04 | v4 → v5 | 802 | 部署后页面无样式：网关要求每请求带 sharecode |
| 05 | v5 → v6 | 10573 | 从公共页面改多用户：登录注册、数据隔离、管理后台 |

> 05 号最大，因为这一版新增了 `core/store.py`、`core/auth.py`、三个前端页面和两套测试，
> 不是小修小补。

## 为什么用「快照 + diff」两套

只给 diff，读的人得在脑子里还原代码；只给快照，看不出改了什么。
两套配合，既能复现又能溯源。

`git log` 里的提交 message 写的是同一批依据，可以交叉对照：

```bash
git log --oneline
git show 7fe1561      # 对应 01 号 diff
git show 356da71      # 对应 02 号 diff
```

cd 02-20Days-Challenge
