### ① 运行日志怎么保证连续

日志由程序自己写，不手填。两条触发线：

- **Windows 计划任务**：每天 19:30，跑 `src/tools/daily_run.py`，关机错过会开机补跑
- **编辑器定时任务**：每天 19:10，跑同一脚本后 `git commit` + `git push`

> 说明：提交脚本一度按 `08:10 / 19:30` 双时段注册，但 7 天日志里从无 08:10 记录。
> 实际触发为 19:30（7/7 天）与 19:10（4/7 天）；另有若干手动补跑时段。这里按日志记录如实描述。

脱敏规则写在 `src/core/telemetry.py`，靠**字段白名单**强制：不在名单里的键直接丢弃，
通知原文永不入日志。每条记录含时间戳（精确到分钟）、会话哈希、耗时、成功与否、错误类型。

11-17 当天日志里有 2 条真实错误记录（`error_rate: 1.32%`），来自解析评测的失败用例，
保留未删——程序真跑才会留下这种需要排查的错。

### ② 迭代记录怎么看

`iterations/` 下六个目录，每个都是**完整可运行**的源码快照，不是 diff 片段；
相邻版本的结构化 diff 另放在 [`iterations/diffs/`](iterations/diffs/)：

| 版本 | 一句话 | 触发依据 |
| --- | --- | --- |
| v1_初版解析器 | 四块骨架跑通 | 首个可运行版本 |
| v2_重写地点与材料 | 地点改扫描式、材料改四步流水线 | 评测：地点 50%、材料 62.5% |
| v3_时间区间与起始语 | 识别「A 至 B」区间与「自…起」 | 评测：3 条挂在时间解析 |
| v4_界面与动作修正 | 空态遮挡、动作串词、座机号 | 截图人工核对 |
| v5_线上部署适配 | 云端运行、内联资源 | 发布后页面 403 |
| v6_多用户改造 | 注册登录、数据隔离、管理员后台 | 公共页面无隐私，学生要求独立账号 |

对应的 `git log` 里每次提交的 message 都写明了触发依据，`iterations/README.md` 有详细对照。

## 目录约定

```
02-20Days-Challenge/
├── src/              # 源码，必须能直接跑（python app.py）
├── process_logs/     # 过程日志
│   ├── 2026-11-17.md #   人工过程日志（一天一个 md）
│   ├── telemetry/    #   程序自动日志 JSONL + summary.csv
│   └── reports/      #   每日自动生成的指标日报
└── iterations/       # 迭代留档，vN_说明/，只留能跑的版本
```

**三条规矩**：

1. **日志当天写**。写"今天卡在哪、怎么绕过去的"，不写流水账；
   代码能复现结论，但复现不了当时的判断过程。
2. **迭代不覆盖**。改版就新开一个 `iterations/vN_说明/`，别把上一版删掉。
3. **`src/` 必须是能直接跑的**。跑不通的半成品放 `iterations/` 里。
