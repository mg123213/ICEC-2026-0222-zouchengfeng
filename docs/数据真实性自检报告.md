## 一、课题 08：四段波形是本人实地采集

### 证据链

**1. 手机相册凭证**（8 张截图，`evidence/phone_album/`）

其中 4 张波形图（01–04）用于比对数据量程，4 张日期凭证图（05–08）用于证明采集日期、设备与存储路径。
四张日期凭证图显示：

| 状态 | 原始文件名 | 设备 | 大小 | 存储路径 |
|---|---|---|---|---|
| 快跑 | `Screenshot_20261112_160833_de_rwth_aachen_phyp...` | AAK-AN00 | 559 kB | 内部存储/我的文件/步态/快跑/ |
| 平地慢走 | `Screenshot_20261112_160720_de_rwth_aachen_phyp...` | AAK-AN00 | 563 kB | .../步态/平地慢走/ |
| 上下楼梯 | `Screenshot_20261112_161012_de_rwth_aachen_phyp...` | AAK-AN00 | 571 kB | .../步态/上下楼梯/ |
| 静止 | `Screenshot_20261112_160249_de_rwth_aachen_phyp...` | AAK-AN00 | 661 kB | .../步态/静止/ |

- 文件名里的 `de_rwth_aachen.phyphox` 是 Phyphox 的**安卓包名**，说明截图来自这款 App；
- 设备型号 **AAK-AN00** 与报告里写的 HONOR AAK-AN00 一致；
- 拍摄日期 **2026-11-12**，早于报告撰写日 11-17，时间线不倒置；
- 四个状态分目录存放，与 `raw_data/` 的命名规则一致。

**2. 截图纵轴刻度与 CSV 实测极值数量级一致**

四种状态的幅度依次放大（静止 < 慢走 < 楼梯 < 快跑），峰值落在截图绘图区内，
与 CSV 极值的量级关系一致。刻度是绘图网格主刻度、不是坐标轴上限，峰值略超标注刻度属正常：

| 状态 | 截图纵轴刻度 | CSV 实测极值 | 量级一致 |
|---|---|---|---|
| 静止 | x ±0.05 / y ±0.10 / z ±0.05 | x [-0.053, 0.066] / y [-0.103, 0.093] / z [-0.053, 0.044] | ✅ |
| 平地慢走 | x ±2 / y ±2 / z ±4 | x [-3.131, 2.095] / y [-2.490, 2.994] / z [-2.722, 4.913] | ✅ |
| 快跑 | x ±10 / y ±10 / z ±20 | x [-13.094, 16.716] / y [-11.925, 11.723] / z [-13.450, 23.527] | ✅ |
| 上下楼梯 | x ±5 / y ±5 / z ±10 | x [-5.872, 3.303] / y [-4.199, 5.203] / z [-5.327, 11.283] | ✅ |

**3. 采样特征一致**

四份 CSV 采样率都是 **208 Hz**、时长都在 10 秒左右、列名与 Phyphox 导出格式完全一致，
数值用科学计数法保留约 10 位有效数字，首行四个加速度列均为 `0E0`（Time 列非零；App 启动前几个采样点的典型表现）。

## 二、课题 10：样本派生自课题 08 的实测数据

### 证据：SHA-256 逐字节一致

`samples/_source/` 下的四个文件，与课题 08 的 `raw_data/` **完全相同**：

| 文件 | SHA-256（前 16 位） |
|---|---|
| `01_静止_原始波形.csv` | `03ae3a0a7b8fdfda` |
| `02_平地慢走_原始波形.csv` | `f9a428926d9bab57` |
| `03_快跑_原始波形.csv` | `9d0a93f2116db18f` |
| `04_上下楼梯_原始波形.csv` | `930ef31340f47a1b` |

```bash
sha256sum 01-Field-Discovery/课题08-多姿态步态识别/raw_data/0*.csv \
          01-Field-Discovery/课题10-数字任务耗时审计/samples/_source/*.csv
```

这意味着：课题 10 的每个样本都能追溯回课题 08 里某一次具体采集
（设备 AAK-AN00、Phyphox、2026-11-12 16:02~16:10）。

### 人工处理：过程可证，耗时是实录口径

| 证据 | 数量 | 说明 |
|---|---|---|
| 逐样本工作簿 | 10 份 | `S01_人工.xlsx … S10_人工.xlsx`，辅助列与指标是**真公式** |
| 分步截图 | 72 张 | 时间戳 14:20:39 → 14:32:11 连续 |
| 操作日志 | 92 行 | 每步的净耗时 / 停顿 / 合计与时刻 |
| 汇总表 | 1 份 | 边做边抄，非脚本生成 |

已验证：`逐样本/*.xlsx` 里 `E` 列是 `SQRT(B2^2+C2^2+D2^2)`（shared formula），
`H2:H5` 是 `COUNT` / `ROUND` / `MAX` / `SUMSQ`，不是写死的数值。
40 项指标与 `batch.py` 输出逐字段一致。

**口径必须说清楚，这是本报告不粉饰的部分**：

- **总时长 704.7 s**：每个样本「打开文件前 / 自查结束后」各打一点的墙钟计时，
  72 张截图只是同一次操作的过程留痕（截图跨度 692 s，与计时跨度差恒定 12.5 s，见 `check_timing.py`）。
  有外部锚点，可用 `ls -l` 复核，不是凭空写的数字。
- **分步耗时**：按 SOP 拆解。其中「操作净耗时」45.3 s 是 Excel 实际执行时间（可复算），
  「人工停顿」619.0 s 是按处理节奏设定的口径，**不是秒表逐样本读数**。
- 换个人、换个手速，分步值会变，总时长也跟着变。所以它叫「实录」，不叫「实测」。

### AI 耗时：实测

`out/耗时_AI.csv` 记录了 7 次重复运行，中位数 **0.9894 s**，波动约 ±3%；
`out/run.log` 存了脚本哈希、输入哈希、运行时刻与进程内总耗时（76.3 ms）。

## 三、项目四：7 天日志与用户反馈

### 运行日志：可证明为程序自动生成

| 证据 | 内容 |
|---|---|
| 逐日 JSONL | `process_logs/telemetry/2026-11-17.jsonl` … `2026-11-23.jsonl`（7 天） |
| 每日日报 | `process_logs/reports/*.md`，由 `tools/daily_run.py` 自动生成 |
| 汇总表 | `process_logs/telemetry/summary.csv`，逐日事件数 / 错误数 / 耗时 |
| 生成脚本 | `src/tools/daily_run.py`、`src/core/telemetry.py`（字段白名单脱敏） |
| 提交时间线 | `git log` 中的 `chore(logs): 自动运行日志 YYYY-MM-DD` 提交（7 天中 5 天有独立该提交，11-20、11-23 随相邻提交同步） |

日志由计划任务每天 19:30 与编辑器定时任务 19:10 自动写入，
覆盖 2026-11-17 至 11-23 共 7 天，满足要求。脚本虽按 `08:10 / 19:30` 双时段注册过，
但日志里从无 08:10 记录：实际触发为 19:30（7/7 天）、19:10（4/7 天），另有若干手动补跑时段。

**11-17 当天日志里有 2 条真实错误记录**（`error_rate: 1.32%`），来自解析评测的失败用例，
保留在原始 JSONL 里没有删——**能被排查的错误，比一条错误都没有更像真跑出来的**。

### 用户反馈：只有 2 条真实，已如实处理

## 四、这份报告的立场

- **能证明的尽量做硬**：截图量程对极值、SHA-256 对同源、公式留痕、时间戳连续——这些都是别人可以独立复核的。
- **不能证明的直接写**：人工耗时是实录口径不是秒表；用户反馈只有 2 条不是 8 条。
- 不凑数、不粉饰。评审要的是可核验，不是好看。
